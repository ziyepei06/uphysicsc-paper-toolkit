# UPC paper template — standalone LaTeX project

A working paper, not an empty shell: it compiles to 11 pages, passes the
built-in checks, and carries a complete worked example (a hull-breach
blow-down problem) whose numbers come from the code in `code/`. Replace
the content, keep the structure. Everything needed is inside this folder —
no external skill, no extra paths.

## 快速开始

```bash
cd UPC-LaTeX-Template
make                # 编译并跑合规检查（队号、摘要词数、参考文献等）
make pdf            # 生成交稿文件名，如 000A.pdf
```

目录里已经带了一份编译好的 `000A.pdf`（11 页）可以先看效果；重新编译会覆盖
`main.pdf`，`make pdf` 会生成 `000A.pdf`。

改三处即可开写：`config.tex`（队号/题号/标题）、`sections/00-frontmatter.tex`
（Abstract/Summary）、`sections/01`–`09`（正文）。所有章节已按金牌论文的结构排好，
每节开头有 `%% GUIDE` 注释说明该写什么。

## Quick start

```bash
make                                    # latexmk + compliance checks
make pdf                                # -> <team><letter>.pdf (e.g. 000A.pdf)
python3 code/blowdown.py                # reproduce the numbers in the text
python3 scripts/make_example_fig.py     # regenerate figures/example.pdf
bash tools/build.sh main.tex            # compile only, with the log gate
```

Without `make` (Windows, or no GNU make):

```bash
bash tools/build.sh main.tex
python3 tools/check_pdf.py main.pdf --team 000 --problem A
python3 tools/count_summary.py main.tex --tex
```

## File map

| Path | What it is | Who edits it |
|---|---|---|
| `config.tex` | team number, problem letter, title — three lines, nothing else | lead only |
| `preamble.tex` | packages, page geometry, header/footer, notation macros | lead only |
| `main.tex` | `\input` order, bibliography | lead only |
| `sections/00-frontmatter.tex` | page 1: the four permitted items + summary | lead |
| `sections/01-introduction.tex` … `09-conclusion.tex` | the body, one file per section | section owners |
| `sections/10-appendix.tex` | derivation, code listing, sweep table | methods owner |
| `sections/11-ai-report.tex` | AI-use report, compiled only when `\aiusedtrue` | lead |
| `refs.bib` | real sources only; verify every entry | anyone, by PR/commit |
| `figures/` | vector PDFs, generated by `scripts/` | figure owner |
| `code/` | the code quoted in the appendix | methods owner |
| `tools/` | `check_pdf.py`, `count_summary.py`, `build.sh` — self-contained checks | nobody |
| `notes/` | scratch: derivations, data notes, meeting log | anyone |

## What the skeleton enforces

- **Page 1** holds only team number, problem letter, title and summary
  (`00-frontmatter.tex` is a `titlepage`; the page counter is restored to 2
  afterwards).
- **Team number in the header of every page**, including the title page and
  the appendix (`fancyhdr` with `plain` redefined, not the default).
- **No names, no institution, no acknowledgements** — anything identifying
  the team is disqualified by the rules.
- **Numeric citations** in the order cited (`natbib`, `unsrt`), so `[1]` is
  the first citation in the text.
- **Code in the appendix, method in the body** — `\lstinputlisting` pulls
  `code/blowdown.py`, so the listing cannot drift from what was run.
- **The summary is counted** before submission: 200 words in this example,
  limit 300.

## Multi-person workflow

1. Lead copies this directory to `<team><letter>/`, fills `config.tex`,
   commits. (Dropping `tools/` and renaming `main.tex` is fine, but keep
   `config.tex` and the `sections/` layout.)
2. Everyone edits only their own `sections/*.tex` and `figures/*.pdf`.
   Never edit `preamble.tex` mid-flight without telling the lead: it
   recompiles for everybody.
3. Build before every commit. `tools/build.sh` (or `make`) fails on undefined
   references and missing figures, so a red build is unambiguous.
4. Numbers that appear in more than one place (summary, results, conclusion)
   come from one file: write them in `notes/numbers.md` and copy from there,
   or define them as macros in `config.tex`. Divergent digits between the
   summary and the conclusion are the single most common self-inflicted
   deduction.

## The worked example, and why it is worth keeping

The example problem is a pressure-hull breach: how long until a
628 m³ module falls to 0.3 p₀ through a circular hole. It is chosen because
it exercises every part of the skeleton — a layered model, a calibrated
parameter, a scaling law, an error budget, a figure generated from the same
code that produced the table. The numbers in the text are not decoration:
`code/blowdown.py` prints 285.5 s for d = 10 cm, and the paper quotes
286 s, rounded to the uncertainty.

Replacing the content:

1. Delete the body of `sections/01`–`09`, keep the `%% GUIDE` comments.
2. Keep `03-assumptions.tex` structure (one row per assumption with a
   quantitative check) — it is the section most teams under-write.
3. Point `\includegraphics` at your own figure, delete `figures/example.pdf`
   and `code/blowdown.py`, and update `10-appendix.tex`.
4. Replace `refs.bib` entries with sources you have actually read.

## AI disclosure

`sections/11-ai-report.tex` is compiled only when `config.tex` sets
`\aiusedtrue`. With the switch off the PDF has no such section at all — which
is the correct state when no generative tool was used, and the reason you must
not add a "no AI was used" paragraph.

The committed sample `000A.pdf` is built with `make demo`, which defines
`\AIREPORTDEMO` on the command line so the section appears; that is how you can
see what a finished disclosure looks like. Your own `make` follows `config.tex`
and stays silent until you flip the switch.

Turn it on if an assistant touched the text, the code, the figures or the
analysis. The section follows the official rule in order: a table of systems
(version, date, interface, purpose), a statement of what was done without AI,
a numbered table of queries with the verbatim prompts, and the complete
outputs, one block per query. Outputs are long — team 765 (2025, gold) spent
five pages — so keep the log short by not delegating work you can do yourself.

## Known limits of the skeleton

- Single column, US Letter, 12 pt — the majority choice in the 74 gold
  papers, but 18 of them are two-column. Switch in `preamble.tex` (comment
  block at the bottom explains the geometry changes).
- The `listings` style is plain; if your code has long lines, set
  `breaklines=true` in the `\lstset` block rather than shrinking the font.
- `natbib` numeric mode: if you need author–year, change the two options in
  `preamble.tex` and `\bibliographystyle` in `main.tex` together.
